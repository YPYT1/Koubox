# 口播匣产品简介 UI 设计

## 设计定位

首页不是营销落地页，而是桌面工具箱的入口。用户打开软件后，第一眼应该知道：

- 这是口播匣；
- 软件有两个可以直接使用的工具；
- 两个工具分别处理视频素材和字幕文件。

视觉采用浅色桌面工具风格：白色工作区、浅灰侧栏、细边框、低饱和状态色、低圆角，不使用渐变背景、夸张阴影、版本宣传语或 AI 仪表盘装饰。

## 首页结构

```text
左侧导航                  主工作区
┌──────────────┐          ┌────────────────────────────┐
│ 工作区       │          │ 搜索工具                    │
│ 工具箱       │          ├────────────────────────────┤
│ 模型与环境   │          │ 口播匣                      │
│ 全局设置     │          │ 视频素材与字幕处理           │
│              │          │ 简短说明                    │
│ 已打开       │          │ 素材获取 / 精准 SRT           │
└──────────────┘          ├────────────────────────────┤
                           │ 工具卡片网格                │
                           └────────────────────────────┘
```

## 简介文案

主标题：

```text
视频素材与字幕处理
```

辅助说明：

```text
从视频链接提取素材，或从本地音频生成可导入剪映的字幕文件。
```

能力摘要：

- 素材获取：下载、抽音、识别（本地翻译暂未启用）
- 精准 SRT：音频与原稿生成字幕时间轴

## 工具卡片

### 爆款素材获取

```text
输入视频链接，下载视频、抽取音频并识别原文；本地翻译暂未启用。
```

入口动作：`打开工具`

### 精准 SRT 对齐

```text
导入音频和可选原文，输出可直接导入剪映的标准 SRT。
```

入口动作：`打开工具`

## 交互原则

- 搜索只过滤工具，不做复杂的全局搜索结果页。
- 首页始终展示两个工具；工具打开后进入左侧“已打开”。
- 翻译链路后端仍保留，产品侧暂不展示翻译入口与结果区。
- 需求二根据是否填写原文自动分为“原文对齐”和“音频识别”。
- 模型与环境页面只展示 GPU、模型完整性和媒体组件状态。
- 状态文案使用操作性语言，例如“正在提取音频”“SRT 已生成”，不使用营销化描述。
