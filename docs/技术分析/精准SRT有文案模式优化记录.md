# 精准 SRT 有文案模式优化记录

更新时间：2026-09-09

## 问题描述

有文案模式在 turbo 对齐结果未完整保留用户文案时，会触发 `PRECISE_SRT_ALIGNMENT_INCOMPLETE`，随后由上层执行计划切换到 Large v3。当前 fallback 可能重新处理完整音频，导致进度显示从较高阶段回到较低阶段。用户感受到的是进度跳回，不是最终 SRT 静默丢失内容。

有文案模式的另一项问题是：即使最终正文被锁定为用户文案，时间边界仍可能不符合自然口播或日语词语结构。

## 当前代码状态

当前 `python/src/koubox_runtime/precise_srt.py` 使用展示归一化后的正文完全一致校验，不再使用历史 `_mode_a_near_match` 阈值，也不再按字符长度权重重新分配用户文案。

日文对齐失败时，`python/src/koubox_runtime/precise_srt_worker.py` 会先使用 Sudachi 词元化文本重新进行一次声学对齐；该路径仍无法完整保留用户文案时，才将错误交给上层模型执行计划处理。

日文分段当前使用 `SudachiPy + SudachiDict-core`：

- 默认保留 `SplitMode.C` 的复合词；
- 超过字幕限制时按 `C → B → A` 逐级细分；
- POS 规则决定助词、助动词、接尾辞和接头辞的附着；
- 最终切点必须同时满足已对齐时间边界和字幕结构限制。

## 已完成

- 定位模型切换造成进度跳回的调用链。
- 移除按字符权重把用户文案重新分配到时间段的历史方案。
- 引入日文 Sudachi 词边界和逐级细分策略。
- 保留正文锁定校验和上层 fallback 错误路径。
- 完成历史样本的部分验证：模式 A 正文可锁定，部分日文样本的边界召回和条数差仍未达到逐样本门槛。

## 未完成

### 1. 重新完成当前实现的真实回归

历史“turbo 无 fallback”和旧便携包结果对应之前的代码状态。Sudachi 改造后需要重新执行 Python、core、类型检查、构建以及真实日文音频回归，并保存当前版本的原始输出。

### 2. 人工复核日文边界

模式 A 样本 02、09 的边界召回低于 85%；样本 07、09 的条数差超过 10%；模式 B 样本 07 的边界召回为 68.09%、条数差为 20.83%。其中样本 09 的参考 SRT 含偏字符级切点，必须先人工试听，不能直接要求生产代码复刻词内边界。

### 3. 中文语义辅助基准

当前还没有中文翻译、中文自然短语边界和中日对应日语边界数据。后续中文只提供语义停顿信号，日语 Sudachi 边界负责合法切点，人工日语标注负责最终金标准。

### 4. CUDA 日文边界模型

模型已训练完成，但验证 F1 为 `0.606060606060606`，训练标签主要来自自动生成资料。模型尚未使用人工金标准评估，也没有生产加载和推理调用点。必须先完成离线对比，再决定是否接入动态规划评分。

### 5. 增量 fallback

当前 fallback 仍可能从头处理完整音频。增量方案需要识别失败片段、扩展上下文、局部重新对齐、合并时间轴并保持其他片段不变。该方案属于长期架构工作。

## 历史方案说明

### 放宽 near-match 阈值

旧记录曾建议把相似度和长度差阈值放宽，以减少 turbo fallback。当前代码已经移除 `_mode_a_near_match`，因此旧阈值和旧验证结果只保留作历史背景，不作为当前行为说明。

### 有文案模式强制 Large v3

该方案可以作为质量对照实验，但当前没有落地为生产策略。当前策略是保留一次 Sudachi tokenized realign，并在失败时交给既有执行计划处理。

### 按词边界重新分配时间

该方案已经由 Sudachi 原子单元、已对齐词尾和动态规划分段取代。不得使用按字符长度比例切分来伪造日语语义边界。

## 验收要求

完成本记录中的未完成项前，不把“正文完整”和“边界质量达标”合并为一个结论。最终验收至少要分别报告：

- 正文一致率；
- 日语合法词边界率；
- 人工金标准边界 Precision、Recall、F1；
- 字幕最大时长和最大字符数；
- fallback 次数和是否从头重试；
- 中文辅助信号映射成功率；
- GPU 型号、显存峰值和模型版本。
