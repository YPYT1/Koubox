# 并发下载优化方案

## 🎯 问题现象

同时使用「视频下载工具」和「爆款素材获取」下载 Instagram 等平台视频时，解析速度非常慢。

## 🔍 根本原因

### 1. 并发限制
- 当前 `maxConcurrentTasks` 默认为 **1**
- 所有任务排队执行，实际上是**串行**而非并发
- 每个任务都要经历：公开解析（25 秒超时）→ 登录态兜底

### 2. 公开解析瓶颈
```typescript
// packages/core/src/public-video.ts:69
timeoutMs = 25_000  // 每次公开解析最多等 25 秒
```

- Instagram 公开解析：抓取 HTML → 解析 JSON → 提取媒体 URL
- 失败后走登录态：启动 yt-dlp → 鉴权预检 → 下载
- **总耗时**：25 秒（公开解析超时）+ 10-30 秒（登录态下载）= **35-55 秒/任务**

### 3. 网络请求重复
- 每个任务独立请求 Instagram 页面
- 没有共享解析结果或连接池
- Instagram 反爬虫限制可能导致请求变慢

## ✅ 解决方案

### 方案 1：提高并发数（立即生效）⭐ 推荐

**修改配置文件并发数：**

```typescript
// 在「全局设置 → 高级」中修改
maxConcurrentTasks: 3  // 改为 3-5
```

**优点：**
- ✅ 无需改代码，立即生效
- ✅ 3 个任务并发，理论速度提升 3 倍
- ✅ 适合 16GB 显存（RTX 5070 Ti）

**缺点：**
- ⚠️ 并发过高可能触发平台限流
- ⚠️ 显存占用增加（ASR 模型约 4GB/任务）

**推荐设置：**
- **仅下载视频**：5-8 并发
- **包含 ASR/翻译**：2-3 并发（受显存限制）

### 方案 3：添加解析缓存（最优但需较多改动）

**设计思路：**

```typescript
// 新增：packages/core/src/public-video-cache.ts
class PublicMediaCache {
  private cache = new Map<string, {
    result: PublicMediaResolution
    expireAt: number
  }>()
  
  async resolve(
    url: string,
    resolver: () => Promise<PublicMediaResolution>
  ): Promise<PublicMediaResolution> {
    const cached = this.cache.get(url)
    if (cached && Date.now() < cached.expireAt) {
      return cached.result
    }
    
    const result = await resolver()
    this.cache.set(url, {
      result,
      expireAt: Date.now() + 5 * 60 * 1000  // 缓存 5 分钟
    })
    return result
  }
}
```

**优点：**
- ✅ 相同 URL 只解析一次
- ✅ 多任务共享解析结果
- ✅ 大幅减少重复请求

**缺点：**
- ⚠️ 需要较多代码改动
- ⚠️ 媒体 URL 可能有时效性（Instagram 签名 URL 通常有效 6 小时）

## 🛠️ 立即可用的优化（推荐）

### 步骤 1：提高并发数

1. 打开「全局设置」
2. 展开「高级」选项
3. 修改「最大并发任务数」：
   - **仅下载视频**：改为 **5**
   - **包含 ASR/翻译**：改为 **3**
4. 点击「保存配置更改」

### 步骤 2：为 Instagram 配置登录（如果还没配置）

1. 打开「全局设置 → 平台登录」
2. 展开「Instagram」
3. 选择「应用内登录」或「粘贴 Cookie」
4. 完成登录配置

**原理**：Instagram 公开解析成功率很低，直接走登录态更快更稳定。
