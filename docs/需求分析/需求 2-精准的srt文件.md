# 需求 2：精准 SRT（音频 / 字幕时间轴对齐）

## 一句话目标

输入**音频**（可选附带口播文案），产出可直接导入剪映的标准 `.srt`。

- **有文案**：做精准对齐——字幕文字以你提供的文案为准，时间轴与声音对齐、断句合理。
- **无文案**：仅靠 ASR 识别出字幕与时间戳（精度与错字属识别能力范围，不承诺「字字正确」）。

---

## 周期与资源

- 周期：约 4 天
- 主力 GPU：RTX 5070 Ti（效果与速度优先；2060 可作降级验证）
- 网络：国内外分流（模型与资料）

---

## 两种输入模式

| 模式 | 你提供 | 流水线 | 字幕文字来源 | 精度预期 |
| --- | --- | --- | --- | --- |
| **A 精准对齐** | 音频 + 文案 | `asr` → `align` → `export_srt` | **你提供的文案** | 高：解决抢先/滞后、断句可读 |
| **B 仅音频** | 只有音频 | `asr` → `export_srt` | **ASR 识别结果** | 中：类似剪映识别，可能有错字/漏字 |

补充输入：

| 情况 | 怎么走 |
| --- | --- |
| 只有文案、没有音频 | 可选先走 `tts` 得到音频，再进模式 A |
| 已有外部 TTS/录制音频 | 跳过 `tts`，按有无文案进 A 或 B |

**模式选择规则（产品）**：有文案 → 默认模式 A；无文案 → 模式 B。界面上可明示两种路径及预期差异。

---

## 业务说明与痛点

制作流程现状（模式 A 要解决的主痛点）：

1. 已有口播文案（多为日文等，示例见下）
2. 文案 → TTS → 得到音频（或外部已有音频）
3. 音频 + 视频素材导入剪映
4. 使用剪映「字幕识别」（本质仍是声音转文字）

痛点：识别出的字幕与声音时间线对不上——声音已到下一句，字幕还在上一句，或字幕抢先出现；断句也不够完整、合理；且识别字可能与原稿不一致。

**解决方向**：

- **模式 A**：不把 ASR 认出的字当最终字幕；用「已知文案 + 音频」对齐出时间轴，再导出 SRT。
- **模式 B**：没有文案时，只能走 ASR 识别 → 直接导出 SRT（与需求 1 后半段能力同源，本需求提供「本地导入音频出 SRT」入口）。

### AI 介入说明（避免误解）

| 步骤 | 要不要模型 | 说明 |
| --- | --- | --- |
| `asr` | 要 | 本地语音识别模型；出带时间戳的片段 |
| `align`（仅模式 A） | 要 | 对齐模型/强制对齐算法（不是聊天 LLM）；**字用原文，时间从音频估** |
| `export_srt` | 不要 | 纯代码写标准 `.srt` |
| LLM 改写/翻译 | 本需求不做 | 翻译归需求 1 |

### 文案示例（模式 A 输入形态）

```
一度だけ言います。 この動画は6時間後に削除します。
今、東京市場では日経もTOPIXも高値圏にあります。
…
（完整文案由业务侧提供；积木只要求「纯文本文案」货物）
```

## 流水线（搭积木顺序）

```
Audio（必有；若只有文案可先 [tts] → Audio）
  │
  ├─ 有文案 Text ──→ [asr] → [align] → [export_srt] → SRT   // 模式 A
  │
  └─ 无文案 ────────→ [asr] ─────────→ [export_srt] → SRT   // 模式 B
```

说明：

- `asr` 与需求 1 同一块积木（听音频、出带时间戳的识别结果）
- `align` 是需求 2 的关键新积木（**仅模式 A**）：用**已知原文**贴回识别结果，校正时间轴、合理断句；避免「又识别错一版文案」当最终字幕
- 模式 B **不跑** `align`；字幕文字以 ASR 为准
- 最终把 `Transcript` 交给 `export_srt`

## 本需求用到的积木

| 积木 | 输入 | 输出 | 来源 | 模式 |
| --- | --- | --- | --- | --- |
| `tts` | 文案文本 | `Audio` | 需求 2 新增；也可接受外部已生成音频 | 可选（仅文案无音频时） |
| `asr` | `Audio` | `Transcript` | **复用**需求 1 / 公共积木 | A、B 都用 |
| `align` | 原文案 + `Transcript` + `Audio`（按实现需要） | 对齐后的 `Transcript` | 需求 2 新增 | **仅 A** |
| `export_srt` | `Transcript` | `SRT` 文件 | 公共积木（需求 1 也可选用） | A、B 都用 |

## 验收标准

### 模式 A（音频 + 文案）

- [ ] 给定文案 + 对应音频，输出合法 `.srt`
- [ ] 字幕**文字与提供文案一致**（不以 ASR 错字为准）
- [ ] 抽查多句：字幕出现区间与听到的语音基本同步（无明显抢先/滞后一整句）
- [ ] 断句完整、可读，适合短视频口播（不无意义碎切、不把一句撕成难以阅读的碎片）
- [ ] 可跳过 TTS：直接提供音频 + 文案仍能出 SRT

### 模式 B（仅音频）

- [ ] 仅提供音频也能输出合法 `.srt`
- [ ] 字幕文字来自 ASR；界面或文档说明「可能有错字，有文案请用精准对齐」
- [ ] 片段含可用时间戳，可导入剪映

### 共用

- [ ] `asr` / `export_srt` 等与需求 1 共用同一实现，无拷贝粘贴第二套
- [ ] 有/无文案时自动或手动走对分支，不混用 `align` 逻辑
