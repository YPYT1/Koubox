# 需求 1 与需求 2：重合部分（可复用积木与货物）

本文定义**契约优先流水线**里，两边共用的「货物」和「积木」。  
原则：积木只认货物，不认需求编号；需求只负责组合顺序。

总览见：[[总需求]]  
流水线见：[[爆款视频、音频、文案获取-需求1]]、[[需求 2-精准的srt文件]]

---

## 1. 为什么说「重合」

表面都有「音频 → 识别 → 文本」，但目的不同：

|        | 需求 1       | 需求 2            |
| ------ | ---------- | --------------- |
| 音频从哪来  | 下载的视频里抽    | 本地导入 / TTS / 外部已有 |
| 文案是否已知 | 未知，要靠识别得到  | **可选**：有文案走精准对齐（模式 A）；无文案只靠 ASR（模式 B） |
| 更关心什么  | 内容对不对、能否翻译 | 导出剪映可用 SRT；有文案时时间轴与断句优先 |

因此重合的不是整条业务，而是下面这些**可复用积木 + 统一货物格式**。

---

## 2. 统一货物（Artifact）

先定格式，再写积木。名称可在实现时微调，语义保持一致。

| 货物 | 核心字段（概念） | 谁生产 | 谁消费 |
| --- | --- | --- | --- |
| `URL` | 链接、平台类型 | 用户 | `download` |
| `Video` | 本地视频路径、时长、来源 | `download` | `extract_audio` |
| `Audio` | 本地音频路径、采样率、时长 | `extract_audio` / `tts` | `asr`、`align` |
| `Text` | 纯文案字符串、语言（可选） | 用户 / 业务 | `tts`、`align`、`translate` |
| `Transcript` | **片段列表**：每段 `text` + `start` + `end`（必须有时间戳） | `asr`、`align` | `translate`、`export_srt`、展示层 |
| `Translation` | 中文文本（可与片段对齐，或先做全文） | `translate` | 展示层 / 后续需求 |
| `SRT` | 标准字幕文件路径或内容 | `export_srt` | 剪映等 |

**硬约定**：`Transcript` 禁止只有「一整段纯文本、没有时间」。  
需求 1 可以暂时只展示拼接后的全文，但积木输出必须带片段时间戳。

---

## 3. 可复用积木（两边都会用或预留给组合）

| 积木 | 变换 | 需求 1 | 需求 2 | 说明 |
| --- | --- | --- | --- | --- |
| `extract_audio` | `Video` → `Audio` | ✓ | 可选 | 统一抽音与格式 |
| `asr` | `Audio` → `Transcript` | ✓ | ✓ | **核心共用**；本地 GPU；输出带时间戳 |
| `translate` | `Transcript`/`Text` → `Translation` | ✓ | 可选 | 译中文 |
| `export_srt` | `Transcript` → `SRT` | 可选 | ✓ | 标准 SRT 写出 |

需求 2 独有、但同样按积木编写（便于以后别的流水线复用）：

| 积木 | 变换 | 说明 |
| --- | --- | --- |
| `tts` | `Text` → `Audio` | 可跳过（已有音频时）；仅「只有文案」时需要 |
| `align` | `Text` + `Transcript`（+ `Audio`）→ `Transcript` | **仅模式 A**：贴回原文、校正轴、合理断句；模式 B 不跑 |

需求 1 独有：

| 积木 | 变换 | 说明 |
| --- | --- | --- |
| `download` | `URL` → `Video` | 可按平台分子积木，统一入口 |

---

## 4. 重合链路（示意）

两边真正共用的能力中枢：

```
        Audio
          ↓
        [asr]
          ↓
     Transcript（text + start + end）
          ↓
    ┌─────┴──────────────┐
    ↓                    ↓
[translate]     有文案 → [align] → [export_srt]   // 需求2 模式 A
（需求1主用）     无文案 → [export_srt]              // 需求2 模式 B
```

---

## 5. 运行时与模型检测（软件层可复用）

与业务积木并列，单独做 **`runtime`**，供软件启动和各积木查询：

| 能力 | 作用 |
| --- | --- |
| 模型注册表 | 登记 ASR / TTS / 翻译等：id、本地路径、用途、检测规则 |
| `check_models` | 检测文件是否存在、是否完整；返回缺失清单 |
| `check_env` | GPU、ffmpeg 等环境项 |
| 配置 | 模型目录、输出目录、是否允许 CPU 降级 |

`asr` / `tts` 等积木**只通过注册表取模型路径**，不在代码里写死盘符路径。  
软件启动 → 先跑检测 → 通过后再开放功能页（详见 [[总需求]]「产品形态」）。

---

## 6. 模块化落地约定

1. **一个积木只做一件事**；禁止在 `asr` 里写死「下载」或「写 SRT」。
2. **积木不 import 某个需求的流水线**；流水线依赖积木，反向不允许。
3. **新增需求优先：加积木或加流水线配置**，而不是改旧积木的 if/else 分支堆业务。
4. **先实现需求 1 用到的积木并带上时间戳契约**；需求 2 开工时 `asr` / `Audio` / `Transcript` 应可原样接入。
5. **新模型只改注册表 + 检测规则**，业务流水线不硬编码模型文件名。

## 7. 实现时目录建议（非强制，可调）

```
apps/desktop/         # Electron：主进程 + 渲染进程 UI
packages/core/        # 业务核心（主进程引用）★
  runtime/            # 模型注册表、存在性/环境检测、全局配置
  modules/            # 积木
    download/         # 封装调用 yt-dlp（不重写 yt-dlp）
    audio/
    asr/
    translate/
    tts/
    align/
    srt/
  pipelines/          # 需求1、需求2 的组合
packages/shared/      # 货物类型、IPC 契约
models/               # 本地模型存放（或配置指向外部目录）
vendor/               # 附带的 yt-dlp、ffmpeg 等
```

具体技术选型写回 [[总需求]] 与各需求文档的「技术点」一节。
